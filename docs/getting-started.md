# Getting Started

Welcome! This guide will help you understand the repository structure and get started with your first week.

## Before Week 01

### Accounts You'll Need

Make sure you have access to:

1. **OHSU Email Account** – Used for institutional communication and Teams
2. **GitHub Account** – For version control and project management (you should already have this)
3. **Microsoft Teams** – For lab communication
4. **Prime8 Access** – The Conrad Lab's compute server (Eisa or Don will set this up)

### Set Up Your Computer

**Local tools you'll need:**

- A terminal application (Terminal on Mac, PowerShell or WSL on Windows)
- Git installed locally: https://git-scm.com/downloads
- A text editor (VSCode, Sublime, or any editor you prefer)
- SSH client (built into Mac and Linux; use PuTTY or OpenSSH on Windows)

### Quick Verification Checklist

Before starting Week 01, verify:

- [ ] You can access your OHSU email
- [ ] You can access this GitHub repository
- [ ] You have Git installed locally (`git --version` in terminal should show a version)
- [ ] You can open a terminal and run basic commands
- [ ] Your mentors have confirmed your start date

If any of these are blocked, create a [Blocker Issue](../.github/ISSUE_TEMPLATE/blocker.yml) and your mentors will help.

## Tips for Success

### Take Notes

- Keep a personal notebook of what you learn
- Write down commands that work
- Document errors and how you fixed them
- These notes will help you remember and understand

### Verify Your Work

- Don't assume a command worked unless you see the expected output
- If something seems wrong, verify it independently
- Ask "how would I check if this actually worked?" before moving on

### Ask Questions Early

- It's better to ask and learn than to struggle silently
- "I don't understand" is a complete and valid question
- Mentors expect and welcome questions from learners

### Document Everything

- Write clear, concise commit messages
- Include comments in code explaining the "why"
- Document blockers and how you solved them
- These habits make it easier for mentors to help

### Take Breaks

- Learning is intense; pace yourself
- If you're frustrated, take a walk
- Come back to a problem with fresh eyes
- Overflow your questions to your next meeting if stuck

## Weekly Workflow

Each week follows the same pattern:

1. **Read** the week's Issue and understand the goals
2. **Learn** by reading guides and resources
3. **Do** the practical tasks
4. **Document** your progress in Issue comments
5. **Reflect** on what you learned
6. **Submit** code or work for review
7. **Wait** for mentor approval
8. **Move** to the next week once approved

Stick to this workflow and you'll make steady progress.
